Projects

cumulus-coach

Personal project, in progress. Started Oct 2026

An AWS study coach. It answers from public AWS documentation with citations, looks up a service with a tool when the excerpts are not enough, and says so instead of guessing when the documents do not cover a question.

  • RAG over 10 public AWS doc pages: chunked with overlap and embedded locally into Chroma. The top 3 chunks go to Claude as numbered excerpts, and every claim cites one.
  • A tool-using agent: a Claude tool-use loop calls lookup_service, feeds the result back as a citable source, and stops after 5 rounds. Every answer is structured: text, a refused flag and the cited sources.
  • 18 pytest tests with Claude and Chroma replaced by fakes, so they need no API key, run in GitHub Actions on every push.

Minimum demo done. Next: an eval set of about 20 questions comparing the plain RAG agent with the tool-using one.

Python, Claude API, Chroma, pytest, GitHub Actions

edge-energy-optimizer

Personal project. Phases 1 and 2 done, Oct to Nov 2026

Forecasts a real office building's energy load a day ahead, then controls a simulated heat pump home to cut its heating cost. Two of five planned phases are done.

  • Phase 1: hourly forecast with gradient boosted trees on real meter data (Building Data Genome Project 2). Trained on 2016, tested on all of 2017, split by time.
  • Phase 2: controls a simulated heat pump home in the BOPTEST simulator (Docker). A look-ahead heuristic cut heating cost 10% to 16% against a fixed thermostat.
  • Then a model predictive controller: a thermal model fitted from a system identification experiment, plus a 24-hour linear program re-solved every hour. On two unseen test periods it cut cost 14% to 20% against the thermostat and 3% to 8% against the heuristic, with similar comfort.

Phases 1 and 2 are done. Phases 3 to 5 are parked.

Python, scikit-learn, SciPy, BOPTEST, Docker, pytest, uv

Lessons learned

What the projects taught me beyond the numbers, pulled from my dev log.

From edge-energy-optimizer

  • Split by time, never shuffle. The model trained on 2016 and was tested on all of 2017, so it never saw the future it was predicting.
  • Read the bias, not only the error. The forecast ran high by 13.8 kWh because the building used about 8% less in 2017 than in 2016.
  • Find the weak spot. Holidays were it: 61.9 kWh error on holidays against 32.6 on weekdays.
  • Beat the simple option first. The look-ahead heuristic already cut 10% to 16%. The predictive controller had to beat that too, and did, by 3% to 8%.
6

From cumulus-coach

  • Refuse in code before calling the model. A distance cutoff turns away far-off questions before any API call, so they cost nothing. The system prompt is the second layer, not the only one.
  • Pick thresholds from measurements. On-topic and off-topic questions never overlapped, but near-topic ones did, so the 1.1 cutoff leaves the hard cases to the prompt instead of pretending a number can settle them.
